## Repeating and conditional controls

Predictor begins with one exam row, allows up to five, and prevents removal of the last row. Each row contains **exam** select, conditional **otherExamName** text, score number, and percentile number. Every row needs at least score or percentile. The stable row `id` exists only for Vue keys/focus and is never transmitted or stored. HTML names use `exams[0][exam]` etc.; API mapping constructs structured exam objects in displayed order. GDPI names such as `appliedColleges[0]` become arrays, with empty slots omitted by validation.

Exam options: `cat`, `xat`, `cmat`, `mat`, `nmat`, `snap`, `mah-mba-cet`, `other`. Other requires its name; changing away clears that name. Specializations: `marketing`, `finance`, `human-resources`, `operations`, `business-analytics`, `other`, `undecided`. Other requires otherSpecialization; stale details are rejected and the control clears when deselected.

Application permits exam without result, but any score/percentile, including zero, requires exam. Start has the same dependency between bestScore/bestPercentile and entranceExams. Study levels: `undergraduate`, `postgraduate`, `mba`, `other`; Other requires otherStudyLevel. Destination values are the nine actual IDs: `usa`, `uk`, `canada`, `australia`, `france`, `germany`, `malaysia`, `uae`, `georgia`. Mentor programs: `mba`, `engineering`, `study-abroad`. Start stages: `exploring-colleges`, `have-shortlist`, `ready-to-apply`, `applications-submitted`, `preparing-gdpi`.

## Validation, normalization, and reconciliation

All forms used novalidate plus explicit native validation, custom conditional errors, reportValidity, inline errors, and first-invalid focus. Success previously meant preview validation only. Existing tests used node:test/assert, TypeScript stripping, esbuild/Vue template compilation and SSR, plus lightweight source checks. Existing tests and their bytes are preserved.

The authoritative server contract already limited names/cities to120, raw phone32, email254, messages/notes/helpNeeded3000, most short text150, application graduationYear20/graduationScore50/exam80/feeRange100/preferredColleges2000, Start entranceExams250/collegeShortlist2000, and Study intake100. GDPI permits at most 3 colleges per list, max 150 per string. Predictor permits 1–5 rows. These limits remain; meaningful punctuation, Unicode, and message line breaks are retained without HTML escaping.

Phones retain an initial plus and 7–15 digits, stripping established presentation punctuation; mobile is stored as a string. Email trims and lowercases. Empty optional values become omitted. Incoming Study name normalizes to fullName through the preserved validator interface, then maps to database name. Browser payloads still use the original Study name field. Study mentor has no email control and therefore receives nullable email.

Percentiles accept 0–100 inclusive with arbitrary decimal step. Scores retain signed decimal/exponent input with the existing finite magnitude guard of 1000000. Budgets retain 0–100000. Zero is supplied, not blank; negative zero now canonicalizes to 0 for JSONB retry consistency. Numeric strings are normalized to numbers; hexadecimal, Infinity, booleans, and object coercion are rejected.

Differences found: most native inputs did not declare contract maxlength, tel had no native phone pattern, budget HTML min0/step0.1 lacked the contract maximum, and score HTML was unbounded. Rather than redesign controls or duplicate rules, every submission now also runs the authoritative shared Zod validator in the browser. The same schemas run on Nitro. Unsupported fields, shapes, enum values, stale Other details and controls are rejected; issue paths map back to named controls. Native constraints and conditional zero-safe behavior remain.

Privacy and terms were unpublished empty slots; no policy was invented. Shared disclosure/success text previously denied saving and has been updated to actual enquiry saving. No unrelated page, route, style, asset, or editorial content changed during Phase B.
